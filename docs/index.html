Voice Relay · Architecture

Voice Relay puts a small dictation button over every app on an Android phone. Double-tap it, speak, and the text lands where you are typing, transcribed by OpenAI with your own API key. It can also fix the grammar of text you typed, and listen on the phone for "hey claude", or a wake phrase you choose, to open the Claude app in voice mode. This page shows how audio becomes text, how the text gets into another app's field, how the wake word decides when to listen, and what leaves the phone.

Backend

Everything runs in one Android app. An accessibility service hosts the floating button and types into other apps; OpenAI does the transcription and the cleanup; a 5 MB keyword-spotting model runs the wake word locally. There is no server of ours in between, no account, and no analytics.

Dictation pipeline

A double-tap starts the recording and a tap sends it. The TLS connection to OpenAI is opened while you are still talking, so the upload starts without a handshake. Hover a box for the details.

A failed request keeps the audio, on disk, so it survives a restart: the button turns amber with a warning badge, a tap sends the same recording again, and a long-press asks to discard it. A long-press while a request is still out gives up on it and keeps the recording for a retry; every request ends by itself after 3 minutes.

On the lock screen a recording stops after 2 minutes, and after 5 recordings the button asks you to unlock.

  • Finding the field. Live input focus first, service-wide and then in every interactive window, retried briefly because web views build their tree lazily. If focus is gone by the time a long dictation is transcribed, the field that was focused when recording started, or the last one you typed in, is used if it is still on screen.
  • Inserting. ACTION_SET_TEXT writes the text at the cursor, replacing any selection, with a space when it follows a word. The clipboard is not touched. Surfaces that refuse it (Termux, password fields) get a paste instead.
  • Undo. For 5 seconds a chip beside the button puts the field back as it was, unless you have edited it since. The previous text is kept in memory only for that.
  • The arrows keyboard draws nothing, reads no text and has no network code. The accessibility service switches to it when you touch the pad and back to your keyboard afterwards, or at once when you tap into a text field.

Grammar fix

Two ways in, one request: the text goes to the Responses API with the grammar-fix prompt and store: false, and the same plausibility guard rejects a reply that is not a fix.

Long-press the floating button · accessibility
  • Fixes the selection, or the whole focused field when nothing is selected. Password fields are skipped.
  • Checks the field has not changed while the request was out, then replaces just that range. Undo works as for dictation.
Fix grammar in the text-selection menu · PROCESS_TEXT
  • Works in any app that offers the standard selection menu, and needs no accessibility access.
  • The calling app replaces editable text itself; read-only text (a web page, a received message) is fixed onto the clipboard.
  • The activity is exported, so any app can call it. It accepts at most 10 requests a minute.

Wake word

A microphone foreground service feeds 100 ms of 16 kHz audio at a time to a sherpa-onnx keyword spotter. When it hears "hey claude" it lets go of the microphone, opens a new chat in the Claude app and presses its Voice Mode button. A small state machine, tested without Android, decides when the microphone is on. The phrase is editable: the app spells a typed phrase as the model's phones with a bundled copy of CMUdict, one keyword line per pronunciation, checks every phone against the model's tokens, and hands the lines to the spotter with each new stream, so a new phrase needs no model reload.

On the way back to listening, if music was playing when the keyword fired and nothing is playing now, the service sends one media PLAY key.

Starting it Android only lets a microphone foreground service start while the app is in the foreground. So it is started from the settings screen, from an invisible activity (Tasker and adb send WAKE_ON, WAKE_OFF or WAKE_TOGGLE to it, unless Allow other apps to control Voice Relay is off), or by the accessibility service when Android rebinds it after a reboot or update. When Android refuses, a notification offers to turn it back on with one tap; it reaches the same activity through a non-exported alias, so it works either way.

Data flow

The only network destination is api.openai.com, reached directly from the phone with your key. If you choose Claude as the cleanup service, the transcript and the text you ask it to fix go to api.anthropic.com with your Anthropic key instead; the audio still goes to OpenAI.

One arrow leaves the phone. The wake word and the arrows keyboard send nothing anywhere.

Leaves the phone, to OpenAI
  • Your recording, for transcription.
  • The transcript, when cleanup is on.
  • The text you ask it to fix.
  • Your vocabulary and language hints, with those requests.
  • With Claude as the cleanup service: the transcript and the text to fix go to Anthropic instead.
Stays on the phone
  • Wake word audio, processed in memory only.
  • The API key, settings and usage counts.
  • Logs: sizes, timings and error messages, never text.
  • What the accessibility service sees.

Settings

One screen, built in code. Defaults are chosen so a new install works with just an API key.

Dictation
  • Transcription model gpt-transcribe, picked from the models your key can use.
  • Live transcription off: streams while you talk instead of uploading after.
  • Languages empty, which auto-detects; codes such as en, es are sent as hints.
  • Vocabulary: names and terms to spell exactly.
  • Clean up transcript on, with gpt-6-luna and a Simple, Dev or Custom prompt.
  • Grammar fix prompt: its own prompt, since that text was typed, not dictated.
Extras, all off by default
  • Wake word, with sensitivity 1 to 7 (default 5) and resume music after Claude.
  • Arrow pad, with automatic keyboard switching.
  • Volume pill: Silent + DND for an hour, Mute, Medium, Loud.
  • Usage: dictations, minutes and an estimated cost from list prices.
  • About: open-source licenses and third-party notices.

Inside the app

One Gradle module in Kotlin. The decisions (pipeline, prompts, wake word states, presets, rate limit) are plain classes with JVM unit tests; the Android classes wire them to the system.

Dictation and text
  • WhisperAccessibilityService: the floating button, gestures, overlays and the dictation state machine.
  • Recorder, AacEncoder, LiveTranscription: capture, encoding, and the Realtime stream.
  • DictationPipeline, OpenAiClient, Prompts: transcribe, clean up, the plausibility guard, and the requests.
  • TextInjector: finding the field, inserting, replacing a range, undo, clipboard fallback.
  • FixGrammarActivity, RateLimiter: the selection-menu fix.
Wake word and extras
  • WakeWord, WakeWordService, WakeControlActivity: the state machine, the microphone service, and the Tasker switch.
  • com.k2fsa.sherpa.onnx: sherpa-onnx's Kotlin bindings, vendored; the native library is built from source in CI with only keyword spotting, and the model is fetched and checksummed at build time.
  • JoystickView, KeysInputMethodService: the arrow pad and its keyboard.
  • VolumePresets, VolumeController, VolumePillView, VolumeTrackView: the presets.
  • MainActivity, LicensesActivity, AppSettings, SecretStore, Usage: settings, licenses, storage, the encrypted key, the usage counter.

Security

The app types into other apps and records your voice, so it asks for a lot. The full model, and how to report a problem, is in SECURITY.md.

What protects it
  • No backend. Requests go straight to OpenAI with your key; nothing else is contacted.
  • Encrypted key. AES-GCM under an Android Keystore key, with app backup off.
  • Local wake word. Its audio never leaves memory; only which keyword fired is logged.
  • Metadata-only logs and clipboard copies marked sensitive.
  • Signed releases built by GitHub Actions from tagged commits; pull requests never see the key.
What you are trusting
  • OpenAI with your audio and the text you send, under your agreement with them.
  • Anthropic, only if you choose Claude as the cleanup service, with the transcript and the text to fix.
  • Other apps with two exported entry points: Fix grammar can spend your key (10 a minute at most), and the control intents can turn the wake word on (only once you set it up) or off, open Claude in voice mode, and hide or show the floating buttons, unless you turn off Allow other apps to control Voice Relay. Use a key with a monthly spend limit.
  • The Claude app once the wake word opens it.
  • The accessibility service, which watches which field is focused in every app and reads a field only when you dictate, fix or undo.

Setup

A few minutes. Each step is in the README, and the status line at the top of the app says Ready when the required ones are done.

Step 1

Install the APK

Download the signed APK from GitHub Releases and open it, or adb install it.

Android 11+arm64
Step 2

Microphone and API key

Allow the microphone on first launch, then paste an OpenAI API key, ideally one with a spend limit.

Step 3

Accessibility service

Turn on Voice Relay in the accessibility settings. On Android 13+, if the switch is greyed out, first use Allow restricted settings in the app's info page.

Ready
Optional

Wake word

Turn it on, allow notifications, and allow Display over other apps so it can open Claude from anywhere.

Optional

Arrow pad and volume presets

Enable the Voice Relay arrows keyboard in the system keyboard settings, and grant Do Not Disturb access for the presets.
